# CrossLab MVP 实施与验收

本清单将参赛原型中的分工表改为完整交付标准。它用于记录验收结果；未填写运行证据的项目不计为已通过。

## 交付目的

CrossLab 面向生化环材研究者，帮助研究者把外领域方法转化为有来源、可修正、可检验的研究方案。首个参赛案例沿用用户原型的“马铃薯块茎形成／多组学 × 最优传输”。核心展示是：改变数据条件后，研究路线、适用条件和最终建议同步改变。

产品的六步链路为：

1. 描述研究问题，确认现象、现有方法、目标和可用数据。
2. 选择跨界方向与具体方法。
3. 查看两侧文献和已有交叉研究，检查论文贡献与迁移推论。
4. 修改映射、证据类型和资源条件，接受、保留待确认或否定关键前提。
5. 确认当前版本的深研计划后执行。
6. 评估并导出方案，包括继续验证、补充条件或暂停当前迁移。

## 功能验收

| 编号 | 操作 | 通过条件 | 运行证据 |
|---|---|---|---|
| F01 | 从空白开始填写研究问题 | 双栏输入卡片可编辑；缺少必要问题时不能继续；文字不会被静默替换 | 待填 |
| F02 | 点击预置方向卡片和自定义方法卡片 | 选择状态清晰，键盘可操作；自定义方法原文保留 | 待填 |
| F03 | 运行文献分析并查看来源 | 文献标题、链接、贡献、适用范围和来源等级可见；预置材料标注为演示 | 待填 |
| F04 | 修改映射或否定前提 | 修改进入当前上下文；报告体现修改；被否定条件影响结论 | 待填 |
| F05 | 尝试直接进入深研 | 未确认当前计划时不能执行；服务端也校验确认与输入指纹 | 待填 |
| F06 | 确认计划后执行深研 | 返回与当前版本匹配的结果；显示执行状态、失败原因和可重试操作 | 待填 |
| F07 | 深研后改变上游问题、方向或条件 | 旧计划、确认、深研和评价退出当前有效结果；必须重新确认 | 待填 |
| F08 | 在深研完成后评估 | 分维度给出理由；未知与低质量分开；允许暂停当前迁移 | 待填 |
| F09 | 刷新页面或重新打开 | 已保存的输入和有效状态恢复；损坏或不兼容的本地存储可恢复为空白 | 待填 |
| F10 | 导出方案和工作流任务材料 | 文件包含输入、版本、来源、映射、计划、建议及运行模式；能辨别待执行任务和完成结果 | 待填 |
| F11 | 窄屏和键盘操作 | 卡片可顺序访问，控件有标签，主体不横向溢出，焦点可见 | 待填 |
| F12 | API 超时、无配置或格式错误 | 页面保留输入；错误可读；旧结果不会被错误请求覆盖；密钥不出现在浏览器或导出文件 | 待填 |

## 研究判断回归场景

| 场景 | 应有的研究判断 |
|---|---|
| 单次采样，希望重建发育轨迹 | 说明缺少时间顺序；收缩为补充采样计划或静态比较，不能生成已验证的发育轨迹 |
| 多时期样本，希望比较发育状态 | 进入设计审查，同时检查组织、材料、重复、批次与分布定义 |
| 暂无可分析数据 | 交付文献假说和数据获取计划，计算状态保持未执行 |
| 目标为预测，却选择解释轨迹路线 | 提示目标与路线需对齐；补充预测目标、数据划分和比较基线 |
| 以最优传输做静态分布比较 | 明确分布、质量、代价函数与简单距离基线，检验稳定性和增益 |
| 把理性疏忽用于生物响应 | 重新定义主体／信号／响应／信息代价及竞争模型；标注识别缺口 |
| 用户明确否定关键迁移前提 | 暂停当前迁移，指出需重建的对应关系；保留理由 |
| 自定义问题与预置案例不一致 | 展示任务原文和模板范围；具体结论需由真实研究服务返回，不能将预置案例当成已检索结论 |

## 文献和科研质量验收

每条核心陈述需要区分论文证据、系统综合推论、待验证假说和实际计算结果。作者自述的贡献与系统的比较判断分开记录。只拿到摘要时记录摘要级来源，缺少全文定位时保留缺口。

对正式参赛版本，建议冻结 6 个任务：2 个已有近似应用、2 个关键条件不满足、2 个有潜力但需补证据。每个任务运行 2 次，由领域人员预先给出参考依据和允许的决策范围。

以下是原型提出的验收目标，执行后填写实测值：

| 维度 | 核验方法 | 目标 |
|---|---|---|
| 证据可靠性 | 人工检查至少 30 条核心陈述的来源和支持关系 | 出处可定位 100%，支持率至少 90%，虚构引用 0 |
| 迁移论证 | 领域人员检查映射、假设、竞争解释、反驳条件 | 主路线关键字段齐全，失效前提明确 |
| 新意核查 | 保存检索式、日期、覆盖范围与最近邻工作 | 已有应用不误称首次，检索不足标为未知 |
| 交互与决策 | 12 次流程及条件修改测试 | 至少 11 次到达正确格式终态；过期结果全部失效 |
| 方案可执行性 | 检查数据、基线、检验和停止条件 | 推进路线有最小验证，暂缓路线有明确补充条件 |

若与“一次提示词生成跨界 Idea”比较，应使用相同资料、尽可能一致的模型和调用预算，记录盲评偏好、耗时及调用量。SciencePal 底座不可控时，将结果描述为工作流比较。技术测试通过与科研质量评测通过分别记录。

## SciencePal 参赛验收

按 [SciencePal AI4Science Hackathon 官方规则](https://sciencepal.ai/hackathon)，至少一个核心环节须实质性使用 SciencePal。CrossLab 将“双侧文献综合与迁移审查”交给 SciencePal，并让其结果影响路线或研究决策。

2026-10-24 已完成真实案例至最终评估。首轮通过 SciencePal 网页发起、官方 API 读回；P2／P5 勘误进入修订 3 后，原生问答、计划、确认后深研与评估均返回真实产物。最终建议为“补充条件后继续”，范围保持为 5 篇文献与设计审查、数据未知时不计算。5 条实际运行已生成可载入案例；界面、生产环境和科学内容的全面人工核验继续进行。运行标识与证据见 [真实运行记录](sciencepal-pilot-acceptance.md)。本清单的每个验收项仍需各自的实际证据。

交付证据包括：

- 可访问的 SciencePal 项目、Agent 或工作流链接。
- 已确认的问题、方法、论文集合与真实任务输入。
- 真实输出、引用和运行标识，能够区分来源平台与本地演示。
- 至少一轮关键条件修订及对应的结果差异。
- 最小验证方案、失败标准和当前未完成事项。
- 模型、数据、代码、API 和外部工具来源；区分赛前已有资产与赛事新增内容。

当前服务端按官方 API 实现异步调用，人工结构化交接作为独立路径保留原始记录。站点可运行、接口配置成功和 SciencePal 对研究决策的实质贡献分别验收。

最终提交还需 3–5 分钟视频、不超过 5 页的项目说明、原创性和资源使用声明。产品无需分工页面；提交材料可按真实完成情况说明贡献。

## 数据与已有成果

原型提到的 183 份马铃薯材料、47,396 个 RNA 特征、678 个代谢特征和 154 份产量来自任务书描述。本仓库不因此取得这些数据，也不将这些数量作为已核验资产。正式分析前核对原始文件、样本表、单位、使用权限、组织和时间信息。

记录一次验收时至少填写：日期、代码版本、运行模式、任务输入版本、预期、实际、证据路径以及未解决问题。不要把本文件的目标表转换为实测成绩。
